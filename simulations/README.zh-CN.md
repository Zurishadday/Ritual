# 模拟

[English](README.md) · [Español](README.es.md) · [Português](README.pt.md) · [Français](README.fr.md) · **中文** · [日本語](README.ja.md) · [한국어](README.ko.md)

课程包中的教训（`web`、`apps`、`crm`、`ai`）并非凭空编造。它们来自观察模型构建某个东西并把它弄坏的过程。每个模拟都是一个现实的任务，按客户会提出的方式撰写，由模型在不使用 Ritual 的情况下构建。然后，另一个模型在另一个会话中运行所构建的东西，并附上证据记录哪里出了问题。出了问题的内容成为教训，标注为 `origin: lab · <模型> · <年-月>`；没有出问题的则不会进入。

## 方法

1. **构建**：使用机械型模型（Sonnet），在一个干净的文件夹中，严格按原样使用 `TASK.md` 的文本，别无其他。它看不到教训、钩子或本文件夹。
2. **审查**：使用判断型模型（Opus），在另一个会话中，依据 `REVIEW.md` 进行。它运行构建的结果，尝试人们实际会走的路径（空输入、错误、双击、移动端、键盘），并寻找那些不会崩溃却依然有误的问题（如密码、未转义的文本）。每项发现都附有证据：命令及其输出，或屏幕上看到的内容。审查者不做任何修复。
3. **撰写教训**：由同一个判断型模型，按五个部分撰写。之后，仓库的人工审核者整合它们：检查其中是否有已被核心覆盖的内容，并运行检查器。
4. **每个任务运行两次。** 两次都出问题的是教训；只出问题一次的，仍是候选项。

每次运行都保存在 `<任务>/runs/<年-月>-<模型>-<n>/` 中（`2026-10-sonnet-1`、`2026-10-sonnet-2`）：保存代码时保持其留下时的样子（它是带有真实错误的示例项目，也是其教训的校准案例），以及 `FINDINGS.md`。

## 如何重复一个模拟

当新模型发布时，任务会重新运行。不再出问题的教训不会被删除，而是被降级（在使用它的项目配置中标记为 `demoted`），运行记录中也会注明。这样，随着模型变好，教训库会依据数据自行缩小。

由脚本完成：`node scripts/simulate.mjs <task>`（例如 `web`）。Sonnet 负责构建，Opus 负责审查，各执行两次，每次都在各自隔离的 Claude Code 会话中进行，脚本再比较两次运行结果：在每次运行中都重现了该课程所描述错误的课程，会以该模型确认；在任何运行中都没有出现该错误的课程，则是降级的候选。请先用 `node scripts/simulate.mjs --probe` 检查隔离情况：负责构建的模型不得看到你的 CLAUDE.md、记忆或插件，并且必须能够启动一个网站并访问它。在维护者通过 `/maintain` 应用之前，库中的任何内容都不会改变。

要提议新任务，请打开一个 issue，写明任务的文字，以及它所代表的项目类型。

## Ritual 有帮助吗？网页任务上的 A/B 测试

同一任务（西班牙语的网页需求）、同一构建者（`claude-sonnet-5-5`）和同一审查者（`claude-opus-5-5`），2026-10，Claude Code 2.1.295–2.1.296。先在不使用 Ritual 的情况下运行，然后加载 Ritual 的钩子，并用 `web` 课程包设置项目（`--with-ritual`）再运行。之后进行返工：同一构建者在不使用 Ritual 的情况下，拿到审查者对某次构建的发现并进行修复（`--fix`），因此构建的成本与修复遗留问题的成本可以完整比较。

| | 出现的错误（共 9 条教训） | 新错误 | 构建 | 修复发现的问题 | 构建 + 修复 |
|---|---|---|---|---|---|
| 不使用 Ritual ([1](web/runs/2026-10-sonnet-5-5-1), [2](web/runs/2026-10-sonnet-5-5-2)) | 7, 8 | 6, 7 | $0.28, $0.27 | $0.53, $0.45 | **$0.82, $0.72** |
| 仅显示问题 ([1](web/runs/2026-10-sonnet-5-5-ritual-1), [2](web/runs/2026-10-sonnet-5-5-ritual-2), [3](web/runs/2026-10-sonnet-5-5-ritual-3)) | 6, 9, 8 | 4, 4, 7 | $0.26, $0.27, $0.27 | | |
| 当前版本的 Ritual ([1](web/runs/2026-10-sonnet-5-5-ritual-v2-1), [2](web/runs/2026-10-sonnet-5-5-ritual-v2-2), [3](web/runs/2026-10-sonnet-5-5-ritual-v2-3)) | **1, 2, 2** | 4, 5, 4 | $0.38, $0.53, $0.60 | $0.24, $0.17, $0.29 | **$0.63, $0.70, $0.90** |

结论：

- **错误：** 九条教训在不使用 Ritual 时平均每次构建出现 7.5 次，使用 Ritual 时为 1.7 次：减少了约四分之三。教训之外的新错误从 6.5 次降到 4.3 次。
- **成本：** 使用 Ritual 构建更贵（每次构建约多 $0.23：它会针对教训来设计，并回头检查一次）。修复遗留问题的成本约减半（金额减少 52%，输出 token 减少 53%：平均从 24,300 降到 11,300）。构建加修复的总成本大致相同：平均 $0.77 对 $0.74，这个差距小于各次运行之间的波动。最终结果从少得多的错误出发，花费却相同。
- **只提问毫无作用。** 只在编写时显示每组问题的版本，结果与不使用 Ritual 的构建相同。真正起作用的是两个部分：开始时的课程包教训，以及收尾（close），它让构建者在完成前回头检查一次。

未能说明的内容：这只是一个任务，每组两到三次运行，且只用了一个模型。未计入发现错误的成本：审查每次构建花费 $1.30–$2.40，两组相同。每份构建和修复报告都注明，它所尝试的命令被拒绝执行 shell，两组皆如此，因此都没有运行过网站：收尾（close）时的自动网页检查从未运行，修复后的内容也没有再次审查。构建者现在和审查者一样拿到 shell 规则，`--probe` 会检查它们能否启动网站。

也不是针对新任务的盲测：

- **同一份考试。** 它计入的九条教训中，有四条（WEB-1 至 WEB-4）源自本任务的第一次模拟，Ritual 的两个部分，即开始时的课程包教训和收尾（close），是在看到这些构建失败后才添加的。它衡量的是 Ritual 在其学习来源的任务上的表现。
- **审查者知道所属的组。** 它拿到构建者的最后一条消息，而使用 Ritual 时，这条消息会用 id 点名教训。
- **审查提示不同。** 两个不使用 Ritual 的构建是在 2026-10-12 审查的，那时审查提示还没有说明审查者的 shell 运行哪些命令；其他所有审查都有这一说明。

## 检查贡献的教训

Ritual 运行在 Claude Code 中，因此只有当错误发生在 Claude 身上时，教训才会在某人的会话中获得一个问题。每条贡献的教训和每次确认，都会注明它发生时所用的模型和月份。

1. **它发生在 Claude 身上，在真实项目中，附有示例：** 以 `field` 收录，并标注该模型，之后经过常规审查（五个部分、匿名、尚未被覆盖）。
2. **它发生在另一个模型上，或者示例存疑：** 维护者会把情况转化为一个小任务，写成客户请求的样子，并用当前的 Claude 模型运行，方法同上。
   - 在 Claude 上出问题：以 `lab` 收录，标注该 Claude 模型，并把贡献者的模型写入 `seen:`。
   - 只在另一个模型上出问题：作为候选项保留在 issue 中，并注明其模型。在有人看到它在 Claude 上发生之前，没有人会收到它的问题。
3. **对现有教训的确认**会把 `<模型> <年-月>` 添加到其 `seen:` 中。被多个模型看到的教训是一般性错误；只被较旧模型看到的教训，是新一轮运行在降级之前首先检查的对象。
