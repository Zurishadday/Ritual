# 시뮬레이션

[English](README.md) · [Español](README.es.md) · [Português](README.pt.md) · [Français](README.fr.md) · [中文](README.zh-CN.md) · [日本語](README.ja.md) · **한국어**

패키지(`web`, `apps`, `crm`, `ai`)의 교훈은 지어낸 것이 아닙니다. 모델이 무언가를 만들고 망가뜨리는 모습을 지켜보며 얻은 것입니다. 각 시뮬레이션은 고객이 요청하듯이 쓴 현실적인 과제로, 모델이 Ritual 없이 만듭니다. 그다음 다른 세션의 또 다른 모델이 만들어진 것을 실행하고, 무엇이 깨졌는지 증거와 함께 기록합니다. 깨진 것은 `origin: lab · <모델> · <연-월>`이 붙은 교훈이 됩니다. 깨지지 않은 것은 들어가지 않습니다.

## 방법

1. **만들기**: 기계적 모델(Sonnet)이 깨끗한 폴더에서, `TASK.md`의 텍스트를 그대로 사용하고 다른 것은 아무것도 쓰지 않은 채 만듭니다. 이 모델은 교훈, hook, 이 폴더를 보지 않습니다.
2. **검토하기**: 판단 모델(Opus)이 다른 세션에서 `REVIEW.md`를 사용해 검토합니다. 만들어진 것을 실행하고, 사람들이 실제로 택하는 경로를 시도합니다(빈 입력, 오류, 더블 클릭, 모바일, 키보드). 그리고 터지지는 않지만 여전히 잘못된 것(비밀번호, 이스케이프되지 않은 텍스트)을 찾습니다. 각 발견 사항에는 증거가 붙습니다. 명령과 그 출력, 또는 화면에서 본 내용입니다. 검토자는 아무것도 고치지 않습니다.
3. **교훈 쓰기**: 같은 판단 모델이 다섯 부분으로 씁니다. 그다음 저장소의 사람 검토자가 이를 통합합니다. 코어가 이미 다루는 내용이 없는지 확인하고, 검사기를 실행합니다.
4. **각 과제는 두 번 실행합니다.** 두 번 모두 깨지는 것이 교훈입니다. 한 번만 깨지는 것은 후보로 남습니다.

각 실행은 `<작업>/runs/<연-월>-<모델>-<n>/`에 저장됩니다(`2026-10-sonnet-1`, `2026-10-sonnet-2`). 남겨진 그대로의 코드(실제 버그가 들어 있는 예시 프로젝트이며, 그 교훈들의 보정 사례입니다)와 `FINDINGS.md`입니다.

## 시뮬레이션을 반복하는 방법

새 모델이 나오면 과제를 다시 실행합니다. 더 이상 깨지지 않는 교훈은 삭제하지 않습니다. 강등됩니다(그것을 사용하는 프로젝트의 설정에 `demoted`로 표시되며, 실행 기록에도 남습니다). 이렇게 해서 모델이 나아지면 라이브러리는 데이터를 근거로 스스로 줄어듭니다.

스크립트가 이 작업을 수행합니다: `node scripts/simulate.mjs <task>` (예: `web`). Sonnet이 빌드하고 Opus가 리뷰하며, 이를 각각 격리된 Claude Code 세션에서 두 번 수행합니다. 스크립트는 실행 결과를 비교합니다. 레슨이 설명하는 실수가 모든 실행에서 발생한 레슨은 해당 모델로 확인되고, 어떤 실행에서도 발생하지 않은 레슨은 강등 후보가 됩니다. 먼저 `node scripts/simulate.mjs --probe`로 격리를 확인하세요. 빌드를 맡은 모델은 CLAUDE.md, 메모리, 플러그인을 볼 수 없어야 합니다. 관리자가 `/maintain`으로 적용하기 전까지 라이브러리는 아무것도 바뀌지 않습니다.

새 과제를 제안하려면, 과제의 텍스트와 그것이 나타내는 프로젝트 종류를 적어 이슈를 열어 주세요.

## Ritual이 도움이 되는가? 웹 과제 A/B 테스트

같은 과제(스페인어 웹 요청), 같은 빌더(`claude-sonnet-5-5`)와 같은 검토자(`claude-opus-5-5`)로, 2026-10에 Claude Code 2.1.295–2.1.296을 사용해 진행했습니다. 먼저 Ritual 없이, 그다음 Ritual의 hook을 불러오고 `web` 패키지로 프로젝트를 설정한 상태(`--with-ritual`)로 진행했습니다. 이어서 재작업이 있습니다. 같은 빌더가 Ritual 없이, 한 빌드에 대한 검토자의 발견 사항을 받아 고칩니다(`--fix`). 그래서 만드는 비용과 남은 것을 고치는 비용을 합쳐 전체를 비교할 수 있습니다.

| | 교훈이 다루는 실수가 나타남 (9개 중) | 새로운 실수 | 만들기 | 발견된 것 고치기 | 만들기 + 고치기 |
|---|---|---|---|---|---|
| Ritual 없이 ([1](web/runs/2026-10-sonnet-5-5-1), [2](web/runs/2026-10-sonnet-5-5-2)) | 7, 8 | 6, 7 | $0.28, $0.27 | $0.53, $0.45 | **$0.82, $0.72** |
| 질문만 ([1](web/runs/2026-10-sonnet-5-5-ritual-1), [2](web/runs/2026-10-sonnet-5-5-ritual-2), [3](web/runs/2026-10-sonnet-5-5-ritual-3)) | 6, 9, 8 | 4, 4, 7 | $0.26, $0.27, $0.27 | | |
| 오늘 Ritual 포함 ([1](web/runs/2026-10-sonnet-5-5-ritual-v2-1), [2](web/runs/2026-10-sonnet-5-5-ritual-v2-2), [3](web/runs/2026-10-sonnet-5-5-ritual-v2-3)) | **1, 2, 2** | 4, 5, 4 | $0.38, $0.53, $0.60 | $0.24, $0.17, $0.29 | **$0.63, $0.70, $0.90** |

이 실험이 말하는 것:

- **실수:** 아홉 교훈이 다루는 실수는 Ritual 없이 빌드당 평균 7.5번 나타났고, Ritual과 함께하면 1.7번이었습니다. 약 4분의 3이 줄었습니다. 교훈 밖의 새로운 실수는 6.5에서 4.3으로 줄었습니다.
- **비용:** Ritual과 함께 만들면 비용이 더 듭니다(빌드당 약 $0.23 더 듭니다. 교훈을 염두에 두고 설계하고, 한 번 되돌아가 확인하기 때문입니다). 남은 것을 고치는 비용은 절반 정도입니다(돈 기준 −52%, 출력 토큰 기준 −53%: 평균 24,300 대 11,300 토큰). 만들기 + 고치기는 거의 같습니다: 평균 $0.77 대 $0.74로, 실행 사이의 편차보다 작은 차이입니다. 같은 비용으로, 결과물은 훨씬 적은 실수에서 시작합니다.
- **질문만으로는 효과가 없었습니다.** 빌드하는 동안 그룹별 질문만 보여 준 버전은 Ritual 없이 한 빌드가 끝난 지점에서 끝났습니다. 결과를 바꾼 것은 시작과 마무리의 패키지 교훈입니다. 이것이 빌더를 끝내기 전에 한 번 되돌려 보냅니다.

이 실험이 말하지 않는 것: 과제는 하나이고, 조건마다 실행은 두세 번, 모델은 하나입니다. 실수를 찾는 비용은 계산에 넣지 않았습니다. 검토는 빌드당 $1.30–$2.40이며, 두 조건이 같습니다. 두 조건 모두에서, 빌드와 고치기는 시도한 명령이 셸에서 거부되었다고 적고 있습니다. 그래서 어느 쪽도 사이트를 실행하지 못했습니다. 마무리 단계의 자동 웹 점검은 한 번도 실행되지 않았고, 고친 것은 다시 검토되지 않았습니다.

## 기여된 교훈 확인하기

Ritual은 Claude Code 안에서 동작하므로, 교훈은 실수가 Claude와 함께 일어난 경우에만 누군가의 세션에서 질문을 얻습니다. 기여된 모든 교훈과 모든 확인에는, 어떤 모델과 어느 달에 일어났는지가 적혀 있습니다.

1. **Claude로, 실제 프로젝트에서, 그 예시와 함께 일어났다면:** 그 모델과 함께 `field`로 들어가며, 평소의 검토(다섯 부분, 익명, 아직 다루지 않은 내용)를 거칩니다.
2. **다른 모델에서 일어났거나, 예시가 의심스럽다면:** 유지관리자가 그 상황을 고객 요청처럼 쓴 작은 과제로 바꾸고, 위의 방법에서처럼 현재의 Claude 모델로 실행합니다.
   - Claude에서 깨진다: 그 Claude 모델과 함께 `lab`으로 들어가고, 기여자의 모델은 `seen:`에 들어갑니다.
   - 다른 모델에서만 깨졌다: 이슈에 후보로 남으며, 그 모델이 기록됩니다. 누군가 그것이 Claude에서 일어나는 것을 볼 때까지는 아무도 그 질문을 받지 않습니다.
3. **기존 교훈에 대한 확인**은 `<모델> <YYYY-MM>`을 그 교훈의 `seen:`에 추가합니다. 여러 모델에서 보인 교훈은 일반적인 실수이고, 오래된 모델에서만 보인 교훈은 강등 전에 새 실행이 가장 먼저 확인하는 대상입니다.
